# 应急调整

真人导游的价值在于现场应变。这个 Skill 的原则是：**Agent 提方案，用户做决定**。

## 步骤

1. **识别冲突**：是什么变了（天气 / 体力 / 排队 / 闭馆 / 时间），影响的是哪几站。
   - 当前在哪一站：看情境里的位置；没有就按当前时间对照行程。
   - 还没有行程：直接给两三条建议，并问要不要排一份新行程。
2. **查资料**：
   - 下雨：读 `references/rainy-day-options.md`，必要时 `amap_weather` 确认。
   - 体力：查 `memory_get` 里同行人的情况。
   - 需要找替代点：读 `trip-planner` 的景点表，用 `amap_route` 算新路线的距离和时间。
3. **生成 2 个备选**，两个方案要有明显区别，例如：
   - A：换（把剩下的户外站换成附近的室内站）
   - B：减（砍掉一两站，提前收尾或找地方歇脚）
   每个方案写清：改了什么、多走/少走多少、几点结束。把完整的新行程放进 `plan` 字段。
4. **调用 `propose_options`**，然后停下来等用户选。**不要自己 `save_plan`。**
5. **用户选定后**（下一轮消息里会带上他选的方案）：调用 `save_plan` 保存那个方案，并简短告诉用户接下来去哪、怎么去。

## 规则

- 体力类问题优先「减」，不要为了凑满行程硬撑。
- 下雨时提醒带伞、走有遮挡的路线；雷暴、台风等极端天气建议取消户外项目。
- 闭馆/排队：先确认是哪一站，再给替代点；不要自己判断「应该没闭馆」。

## 禁止

- 未经用户选择就修改已确认的行程
- 替用户退票、改签、叫车（只给链接）
